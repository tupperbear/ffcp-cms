1 · For editors

Faster publishing

When you click Deploy Website in the CMS, the website is rebuilt with your changes. That rebuild now takes about thirty seconds instead of a minute or more.

RebuildBeforeNow
Live website (familyforestcarbon.org)55 s – 2 min 15 s
typically about 1 min 10 s		28 s
Building the pages themselves40 s7 s

What changed: to build each page, the site used to fetch every image from the CMS just to check its dimensions, which was most of the waiting. It now gets the dimensions of all images in a single request.

2 · Behind the scenes

Right-sized images

Many images in the media library were stored at the full resolution of the original photo — up to 5,300 pixels wide and 13.8 MB for a single image. 92 images were brought to the same standard new uploads already get automatically: at most 2,000 pixels on the longest side, in the modern WebP format.

ImagesBeforeNow
The 92 resized images299 MB37 MB
Largest single image (Greenbiz23 Ad)13.8 MB0.5 MB
All images in the media library360 MB98 MB
Whole media library (284 files)730 MB460 MB

Visitors already received images at the size each page shows them; what changes is the original the site prepares them from, which is now a fraction of the size. Nothing in the CMS needs updating — each image is still in the same place, and image quality on screen is unchanged.

Tip for editors

Publishing works as before: the Deploy Website button, now finishing in about thirty seconds.

Uploads: images are resized automatically when you upload them. For video, linking to YouTube or Vimeo keeps the media library small.

4 · How we kept it safe
  • Every replaced image is kept in the CMS backups, so any original can be brought back.
  • The resizing was tested on a copy of the CMS first, then on a single image, before the rest.
  • After each step the whole website was rebuilt and compared with the version before: all 54 pages came out the same. One tall background image is now requested at a slightly smaller size, by design.
Optional clean-up for FFCP
  1. Unused PDFs — 32 PDFs (243 MB) aren’t linked from the website, including three copies of the 39 MB Apps Practice Overview (May 2024) and several AFF reports. Some may still be linked from old emails, so we left them in place.
  2. Draft and archived content — 54 files are used only by drafts or archived pages (the CMS has 10 draft and 8 archived pages). Removing them would leave those drafts with missing images; is that content still needed?
  3. Old content blocks — 83 content blocks left behind by deleted pages are still stored in the CMS and can be tidied up.

A full list of these files is available on request.
